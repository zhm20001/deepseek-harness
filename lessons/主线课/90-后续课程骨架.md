# 后续课程骨架（节点 4–13）

> 供 agent 生成后续课程用。每节写明：本课回答的问题、预计必记词（生成时必须按源码核实修正）、实例锚点、源码回溯地址、与已学内容的接缝。生成流程与文档模板见 `00-课程规约.md`。主线不变量（贯穿每课当探针用）：① 注册是 effect，卸载必须回卷；② 事件是扩展点，选域先于选包；③ 模型可见 ⟺ 可从日志重建；④ 换 provider 换整个世界，前提是 Definition 不含某个 Consumer 的私有物；⑤ 强制要发生在做决定的那个操作里。

## 节点 4 — Session 事件日志（下一课）

- **回答**：模型看到的一切，为什么必然能从磁盘上的日志重建？"改了历史"为什么是被禁止的？
- **预计必记词（待核实）**：append-only 日志 = 唯一真相源；模型可见 ⟺ 可重建；事件即词表（SessionEventMap）；历史只进不退（迁移不改正文，只加版本）。
- **实例锚点**：一次模型请求的完整历史，从日志重放出来（recorded-session 回放）。
- **回溯地址**：`packages/core/session/src/types.ts`（SessionEventMap）、`packages/core/session/src/index.ts`（append / deriveMessages）、`packages/session/session-persistence-jsonl/`。
- **与前课接缝**：内核的"账本"管内存里的登记；session 是所有插件共享的**磁盘账本**——上一课的"写回"思想在这里变成产品不变量。

## 节点 5 — Agent 抽象与事件域

- **回答**：观察、控制一个 agent，分别用什么事件？一个事件该登记在哪个域？
- **预计必记词（待核实）**：三个事件域（session / agent / capability）；选域三问（在飞观察用哪个、跨重载存活用哪个）。
- **实例锚点**：`agent/pre-step`、`agent/request`、`agent/turn-stopping` 三个真实事件的 mode 判别。
- **回溯地址**：`packages/core/agent/src/dispatch.ts`、`docs/event-producer-consumer.md`、`docs/agent-lifecycle.md`。
- **与前课接缝**：01 课的"推事件"在这里长出词表和归属规则。

## 节点 6 — agent-loop 状态机

- **回答**：一轮对话内部怎么转（turn / step）？取消、重试各落在哪一步？
- **预计必记词（待核实）**：turn = 一次模型调用 + 它的全部工具执行；step；取消发生在提交前/后日志不一样；重试不重跑的部分。
- **实例锚点**：挑一条 recorded-session 回放，把每个日志事件名对回代码位置。
- **回溯地址**：`packages/core/agent-loop/src/agent.ts`、`README.md#understand-the-implementation`。
- **与前课接缝**：loop 是普通插件（01 课）；它的一切状态来自 session 日志（节点 4）。

## 节点 7 — Tools 执行流水线

- **回答**：一次工具调用从模型意图到结果经过哪几道闸？拒绝为什么必须发生在闸上、而不是靠 schema 省略？
- **预计必记词（待核实）**：pre → execute → post 三道闸；审批属于消费者一侧；"schema 省略不算强制"。
- **实例锚点**：审批拦截——01 课 waterfall 例子的正主。
- **回溯地址**：`packages/core/tools/src/index.ts`、`docs/tool-execution-pipeline.md`、`docs/cookbook/adding-a-tool.md`。

## 节点 8 — Prompt 组装与上下文工程

- **回答**：模型每次看到的提示词怎么拼出来？为什么 section 顺序关系缓存？
- **预计必记词（待核实）**：section 顺序；system node 与缓存前缀；"空渲染清空旧 prompt"的语义。
- **回溯地址**：`packages/core/system-prompt/src/index.ts`、`packages/context/*`、`packages/compaction/*`。

## 节点 9 — LLM adapter

- **回答**：换模型厂商为什么不动 loop？
- **预计必记词（待核实）**：消息与流词表 provider 中立；adapter 只做翻译；`prepareCall`。
- **实例锚点**：`llm-deepseek` 与 `llm-pi-ai` 两个 adapter 对照。
- **回溯地址**：`packages/llm/llm/src/index.ts`、`docs/cookbook/adding-an-llm-adapter.md`。
- **与前课接缝**：03 课接缝的又一次兑现——Definition（llm）不变，Provider 随便换。

## 节点 10 — 执行世界（fs / shell / subprocess / sandbox / terminal）

- **回答**：工具怎么安全地碰真实机器？指向远程环境时为什么工具一行不改？
- **预计必记词（待核实）**：三件套配对（fs + subprocess + sandbox）；argv 先包装后执行；策略在哪一步生效。
- **回溯地址**：`packages/fs`、`packages/shell`、`packages/subprocess`、`packages/sandbox` 各自的 Definition 包。

## 节点 11 — 委派与并行（subagent / jobs / workflow）

- **回答**：活儿怎么分出去、怎么收回来？subagent、后台任务、工作流的边界在哪？
- **预计必记词（待核实）**：subagent = 同一接口、极端不同的 transport；jobs = 背景任务的统一登记处；workflow = 编排。
- **回溯地址**：`packages/subagent/`、`packages/jobs/`、`packages/workflow/`。

## 节点 12 — 应用外壳与传输面（boot / profile / web / sdk）

- **回答**：同一棵插件树怎么长出 CLI / 网页 / SDK 三种形态？配置层怎么叠加？
- **预计必记词（待核实）**：层序 bundle → profile patch → home patch → `--patch`（02 课 patch 的正式登场）；SDK 只能选 profile 不能自带插件树。
- **回溯地址**：`packages/boot/app-boot/src/profile.ts`、`apps/cli/src/`、`packages/bundle/`。

## 节点 13 — 复盘与动手

- **回答**：这套 harness 反复用什么手法守不变量？自己加一条最小接缝走一遍全流程。
- **预计必记词**：plugins not loop changes；explicit > implicit；fail loud；branded ids。
- **回溯地址**：根 `AGENTS.md` Conventions、`docs/defensive-patterns.md`、`docs/cookbook/adding-a-package.md`。
- **产出**：按 cookbook 加一个最小 seam（Definition + Provider + 一个工具），测试全绿。
