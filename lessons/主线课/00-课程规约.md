# 课程规约：统一讲法与文档骨架

> 本文档是生成与验收课程文档的唯一标准。agent 按它产出新课；读者也可以把它当作"这些课怎么读"的说明。规约由 2026-09-29 的学情反馈确立：学习者非程序员出身，能记住的是**逻辑**（系统以什么方式运行），记不住的是**源码细节**（类名、函数名、行号）。

## 0. 三条铁律

1. **逻辑层优先。** 每课先回答"这个问题为什么存在"，再讲"系统怎么解决它"。讲机制是为了解释设计，不是复述实现。
2. **必记内容有硬上限。** 每课"记住"栏 ≤ 5 个词。判定标准：**换一个实现仍然成立的词才配记**（如"接缝""配置行即数据"）；绑定具体文件的类名、函数名、状态名一律不配记（如 `ScopedLayers`、`FiberState` 六态名）。
3. **源码只是回溯地址。** 文件行号不进正文讲解，只进文末"源码层"表格。正文若需要细节才能讲对，把细节**化成大白话**放进逻辑层，行号留在表格里。

## 1. 每课文档骨架（模板，按序）

```markdown
# NN — 标题
> 一句导语：本课回答什么问题；与上一课的接缝在哪。

## 逻辑层
### 一、<概念名>（必记词）
四步展开（见第 2 节）。
### 二、…（每课 2–5 个概念）

## 记住什么 / 不用记什么
两栏清单；"不用记"栏同时给回溯提示。

## 源码层（回溯地址，不要求读）
| 想查什么 | 地址 |
|---|---|
（含指向"原始精读版"的行，如有）

## 自测（可选）
≤ 2 题，全部能用逻辑层回答，不要求行号。
```

## 2. 大白话写法：每个概念固定四步

1. **大白话**：第一句禁止出现任何术语，用生活语言说清"这是什么、为什么需要它"。
2. **术语**：给这个词在代码/官方文档里的真名（一句话即可）。
3. **例子**：一个真实包或真实事件（不用虚构代码）。
4. **推论**：一句"所以……"，把例子接到设计意图上。

正面示范（`!!js`，摘自 02 课）：
> 配置文件是写死的文本，但有些值依赖"这台机器"（用户名、路径、开关）。`!!js` 允许你在配置里嵌一小句 JavaScript，装载那一行时当场计算，结果当作配置值。例：`user: !!js "process.env.USER"`——同一份文件，每台机器自动适配。

反面警示：像"interpolate 在 internal/config 钩子里对 `__jsExpr` 节点递归求值"这种句子**不许出现在逻辑层**——它属于源码层。

## 3. 比喻系统（一座楼，不换楼）

全课程只用"写字楼"一座比喻：物业 = 框架，商户 = 插件，招牌 = 服务，前台 = ctx，登记条 = 一次装载，广播 = 事件，账本 = 撤销单，门牌 = isolate。术语总表在 `../01-system-map.md`——**新术语必须同步登记进那张表**，禁止另起比喻。

## 4. 贯穿实例与三问检验

每课至少一个真实实例（真实包、真实事件名，不写假代码）。凡能用"三问"读插件的场景必须用：**它 provide 什么 / inject 什么 / on 什么**。

## 5. 篇幅

逻辑层 ≤ 80 行；整课 ≤ 150 行。超长时先删源码细节，再合并概念——宁可少一个概念，不多一行实现。

## 6. 自测与进度

自测默认可选，不做前置要求；学习者卡住时回溯历史课件（原始精读版保留在 `lessons/` 根目录）。生成新课后：更新 `../README.md` 的进度行与对应节点条目（加"笔记"链接）。

## 7. 生成流程（agent 执行）

1. 读本规约 + `../README.md`（节点清单与当前进度）。
2. 读 `90-后续课程骨架.md` 对应节：确认本课问题、预计必记词、实例锚点。
3. 按骨架给出的源码地址**核实源码**——机制讲错比讲浅更糟；发现骨架预估有误，顺手更新骨架。
4. 按第 1 节模板写课，落盘为 `NN-<名字>.md`。
5. 新术语登记进 `../01-system-map.md`；更新 `../README.md` 进度。
6. 若产出更深的原始精读版（带 demo、行号、自测答案），放 `lessons/` 根目录并在源码层表格里互链；统一版只放本目录。
