# 课程规约：统一讲法与文档骨架

> 本文档是生成与验收课程文档的唯一标准。agent 按它产出新课；读者也可以把它当作"这些课怎么读"的说明。规约由 2026-09-29 的学情反馈确立；2026-10-01 增补：图规约回归、误解栏、三层篇幅制。学习者非程序员出身，能记住的是**逻辑**（系统以什么方式运行），记不住的是**源码细节**（类名、函数名、行号）。

## 0. 三条铁律

1. **逻辑层优先。** 每课先回答"这个问题为什么存在"，再讲"系统怎么解决它"。讲机制是为了解释设计，不是复述实现。
2. **必记内容有硬上限。** 每课"记住"栏 ≤ 5 个词。判定标准：**换一个实现仍然成立的词才配记**（如"接缝""配置行即数据"）；绑定具体文件的类名、函数名、状态名一律不配记（如 `ScopedLayers`、`FiberState` 六态名）。
3. **源码只是回溯地址。** 文件行号不进正文讲解（图也算正文），只进文末"源码层"表格。正文若需要细节才能讲对，把细节**化成大白话**放进逻辑层，行号留在表格里。

## 1. 每课文档骨架（模板，按序）

```markdown
# NN — 标题
> 一句导语：本课回答什么问题；与上一课的接缝在哪。

## 逻辑层
### 一、<概念名>（必记词）
四步展开（见第 2 节）。
〔mermaid 图嵌在它服务的概念之后；选型、预算、语言见第 3 节，配得上才画〕
### 二、…（每课 2–5 个概念；图随概念走，不设总数）

## 记住什么 / 不用记什么
两栏清单；"不用记"栏同时给回溯提示。

## 源码层（回溯地址，不要求读）
| 想查什么 | 地址 |
|---|---|
（含指向"原始精读版"的行，如有）

## 容易想错（可选）
≤ 2 条，每条 = 一句错误认识 + 一句纠正。

## 自测（可选）
≤ 2 题，全部能用逻辑层回答，不要求行号。
```

## 2. 大白话写法：每个概念固定四步

1. **大白话**：第一句禁止出现任何术语，用生活语言说清"这是什么、为什么需要它"。
2. **术语**：给这个词在代码/官方文档里的真名（一句话即可）。
3. **例子**：一个真实包或真实事件（不改虚构代码）。
4. **推论**：一句"所以……"，把例子接到设计意图上。

正面示范（`!!js`，摘自 02 课）：
> 配置文件是写死的文本，但有些值依赖"这台机器"（用户名、路径、开关）。`!!js` 允许你在配置里嵌一小句 JavaScript，装载那一行时当场计算，结果当作配置值。例：`user: !!js "process.env.USER"`——同一份文件，每台机器自动适配。

反面警示：像"interpolate 在 internal/config 钩子里对 `__jsExpr` 节点递归求值"这种句子**不许出现在逻辑层**——它属于源码层。

## 3. 图规约：跟着概念走，配得上才画

图与教学文字同格：它是更形象的正文，受同一套纪律管。本规约说"图"，一律指 **mermaid 图**：写在 ```mermaid 围栏代码块里、随正文一起渲染；不用图片文件，也不用其他作图语法。

1. **选型按内容**：多方来回、分先后 → 时序图（`sequenceDiagram`）；少数状态来回迁移 → 状态图（`stateDiagram-v2`）；结构、分层、谁包含谁 → 流程图（`flowchart`）。
2. **配得上才画**：图承担**文字装不下的信息**才上——多方先后、分支走向、状态迁移、结构分层。复述文字的图删掉。多数课一张图够；不设总数上限，也不为凑数画。
3. **画布预算**：时序图参与方 ≤ 6、消息与分支合计 ≤ 14；状态图状态 ≤ 6；流程图节点 ≤ 14。塞不下说明一张图想讲两个概念——拆图或删概念，不放大图。
4. **图内语言**：参与方与节点写**比喻名（术语名）**（如 `登记条 Fiber`）；不带文件名、行号和正文没出现过的类名；每张图配一行"读法"注记。
5. **行数豁免**：mermaid 代码块的行数不计入第 6 节任何行数上限——图的读负担按画布元素算，不按源码行数算。
6. **地图例外**：`../01-system-map.md` 上的图是回溯辅助，与源码层同侧，不受本节语言规则限制。

## 4. 比喻系统（一座楼，不换楼）

全课程只用"写字楼"一座比喻：物业 = 框架，商户 = 插件，招牌 = 服务，前台 = ctx，登记条 = 一次装载，广播 = 事件，账本 = 撤销单，门牌 = isolate。术语总表在 `../01-system-map.md`——**新术语必须同步登记进那张表**，禁止另起比喻。

## 5. 贯穿实例与三问检验

每课至少一个真实实例（真实包、真实事件名，不写假代码）。凡能用"三问"读插件的场景必须用：**它 provide 什么 / inject 什么 / on 什么**。

## 6. 篇幅：上限管读负担，课题边界管连续性

1. **逻辑层正文 ≤ 80 行（硬上限；不含 mermaid 代码块）。** 超了先删源码细节，再合并概念——宁可少一个概念，不多一行实现。
2. **整课默认 ≤ 150 行（默认值，非硬墙）。** 超限允许，条件须全部满足：逻辑层正文没超；超出部分是图、表格、自测这类低密度内容，或确有整体性理由；导语注明"本课 X 行，超限原因：……"。
3. **拆课只拆在接缝上。** 一个概念的四步展开永远不跨课切开；切割线只能落在概念之间的自然接缝上，且每课至少承载 2 个概念。行数吃紧时按"删减 → 超限注明 → 拆课"的顺序取舍，不许为凑行数把连贯课题切成不连贯的小块。

## 7. 自测、误解与进度

自测与误解栏默认可选，不做前置要求；学习者卡住时回溯历史课件（原始精读版保留在 `lessons/` 根目录）。误解栏优先收**真实踩过的坑**（如原始精读版里"已纠正的误解"）。生成新课后：更新 `../README.md` 的进度行与对应节点条目（加"笔记"链接）。

## 8. 生成流程（agent 执行）

1. 读本规约 + `../README.md`（节点清单与当前进度）。
2. 读 `90-后续课程骨架.md` 对应节：确认本课问题、预计必记词、实例锚点。
3. 按骨架给出的源码地址**核实源码**——机制讲错比讲浅更糟；发现骨架预估有误，顺手更新骨架。
4. 按第 1 节模板写课，落盘为 `NN-<名字>.md`；按第 3 节选型画图，对照画布预算与图内语言自查。
5. 新术语登记进 `../01-system-map.md`；更新 `../README.md` 进度。
6. 若产出更深的原始精读版（带 demo、行号、自测答案），放 `lessons/` 根目录并在源码层表格里互链；统一版只放本目录。
