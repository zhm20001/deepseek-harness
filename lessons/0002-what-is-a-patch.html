Lesson 0002 · dsh 架构

Patch:用 YAML 就能改造 dsh

目标:10 分钟后,你能在不写一行 TypeScript 的情况下,给 dsh 换配置、拔插件、加插件——这是 DIY 的第一级工具。
上节课留下的问题:「patch 到底是什么?」一句话:patch 是一份声明式 YAML,描述「对插件清单做哪三种动作」。上一课我们把插件清单想成一张购物清单——base bundle 一次性写满整张清单,后续每一层 patch 只在清单上做批注:换掉某行、划掉某行、追加几行。

1. 三种动作,就是整个语法

真实文件:packages/bundle/headless/cordis.patch.yml(dsh 无界面模式的全部定制,只有 35 行)。它恰好三种动作各用了一次:

# 动作① 改配置:按 id 定位 system-prompt 行,替换它的 config
- id: system-prompt
  config:
    persona: >-
      You are a coding agent powered by the {{model}} model...

# 动作② 禁用:把 hmr 行从组合里划掉
- id: hmr
  disabled: true

# 动作③ 追加:插入两个全新插件行
- insert:
    - id: code-runtime
      name: '@deepseek-ai/dsh-code-runtime-worker-thread'
    - id: headless-runner
      name: '@deepseek-ai/dsh-headless'
      config:
        task: !!js ctx.headlessStartup.task

行里的字段含义:

字段作用
id这一行的稳定标识,后续所有 patch 都靠它定位这一行(所以 id 永不变,包名可以换)
name要加载的 npm 插件包名
config传给插件 static Config schema 的配置
disabledtrue = 从组合中移除;可写 !!js 表达式按平台/环境条件移除
!!js 表达式config 和 disabled 的值可以是 JS 表达式,如 !!js process.platform === 'win32' 或读环境变量

2. 四条叠加规则

  1. 按 id 定位,整段替换:patch 改 config 时替换目标行的整个 config,不做深合并。所以「某行在各模式下不同」的配置不放 base,放到各模式的 bundle patch 里(base 文件开头注释明确写了这条约定)。
  2. 后写的层赢:同一 id,排在后面的层覆盖前面的层。这就是上一课层叠图(架构地图 · 组合层叠)里 --patch 优先级最高的原因。
  3. 行顺序无加载语义:清单里行的先后不代表加载顺序,激活由「依赖的服务是否就位」驱动(inject 决定)。
  4. 用户层随时可加:你自己写一个 - insert: 小文件,用 dsh --profile X --patch my.yml 挂上即可。真实例子:examples/web-schedule/cordis.yml 整个文件只有 6 行——两个 insert,就给 Web 模式加了一个「定时任务」能力。

3. 这对你意味着什么

dsh 的定制是分级的:配置级(YAML patch,今天就会)、组合级(profile + bundle)、代码级(写插件,下一课)。大部分「我想改一下」的需求止步于第一级。换 LLM provider、换 persona、拔掉某个工具、加一个现成插件包——全是 patch 能完成的,零 TypeScript。

检索练习

Q1. 你想在已有组合里加一个全新的插件包,patch 里该写什么?

三种动作只有 改配置 / 禁用 / insert 追加。新行要给 id(供以后定位)和 name(包名)。

Q2. profile patch 把某行 config 里的 timeoutMs: 60000 改成 30000,该行原有其他 config 字段会怎样?

patch 对目标行是整段替换,不深合并。想保留其他字段就要在新 config 里把它们重写一遍。

Q3. patch 清单里 agent-loop 行排在第 4 位、bash 行排在第 40 位,这意味着什么?

行顺序纯粹是给人读的;启动时机由服务可用性驱动——谁的 inject 先满足谁先活。

动手验证(8 分钟)

  1. 跑 dsh --profile headless --dump-config(在仓库根可 pnpm dsh …),对照输出找到 system-prompt、agent-loop、headless-runner 三行——确认「最终产品 = 叠加后的清单」。
  2. 抄 web-schedule 的 6 行,改成你自己的:写一个 my.yml,内容为 - id: system-prompt / config: persona: 你想要的人设,用 --patch my.yml 挂到 headless 跑一次,看 persona 是否变了。
  3. (可选)在同一文件里再写 - id: agent-loop / disabled: true,再跑一次——亲手复现 第 1 课预测的 no agent factory registered 报错。

本课收获

  • patch = 三种动作(改 config / disabled / insert)的声明式 YAML。
  • 按 id 定位、整段替换、后写赢、行序无语义。
  • 配置级 DIY 已经到手——你现在能改任何 dsh 配置而不写一行 TS。
