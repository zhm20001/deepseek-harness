Lesson 0010 · 真实事故解剖 II

契约是两个人签的——「装好还能用,六天后爆炸」的完整逻辑

目标:15 分钟。这课回答你自己的两个疑问:「1.3k 星的插件怎么会有这种 bug?」和「我装好时明明还能开新对话,那触发原因只有它吗?」。答案的核心是一句话:bug 不属于任何一方,它属于一个「配对」——旧插件 × 新宿主,而把这对组合拼到一起的,是 8/29 深夜的一次 git pull。
这不是编的案例。2026-09-04 晚,你在 dsh web 里选任何工作区都会被"弹回",无法新建对话。上一轮已修复(升级 dsh-context 0.33.1 → 0.41.3);本课把事件的完整逻辑关系讲透——两个当事人的证据全部来自你自己的机器:git reflog、会话日志、投影缓存、npm 发布记录,每一分钟都对得上。

1. 先给结论:这不是「一个插件的 bug」

爆炸需要三个条件同时为真,缺一不可:

条件由谁提供什么时候开始为真
A. 插件在「空白新会话」上产出含 undefined 字段的投影值dsh-context 0.33.1装它的那一刻(8/27)就为真——但无害
B. 宿主把插件投影值塞进「创建瞬间」的广播里新宿主架构(Session Controller)8/29 23:20 你 pull 进来之后
C. 宿主对广播内容做「无损 JSON」校验,不合格就抛错回滚新宿主架构(api-remotes)同上

8/27–8/29:A 真、B 假、C 假 → 平安无事(所以你的记忆没错,装好时确实能开新对话)。8/29 23:20 之后:A 真、B 真、C 真 → 每一次新建会话必炸。你 9/4 才发现,只是因为这六天里你没有点过"新建对话"——打开旧会话走的是另一条路,不经过这段代码。

关键观念:「有没有 bug」不是单个软件的属性,是一对版本的属性。dsh-context 0.33.1 对它出生时的宿主是无害的;宿主的新契约对全新插件也是无害的;病出在配对上。就像老插头在老墙上的插座里没病,墙换成了新国标,老插头才「有病」——病不属于插头也不属于墙,属于这对组合。

2. 三张名词卡(零基础版)

名词卡一:契约(contract)= 双方对数据格式的约定

两个软件部件合作,必须先约好「我递给你的数据长什么样」。这约定叫契约。这次事故的契约是:凡是从宿主广播给浏览器的事件,参数必须是无损 JSON(lossless JSON)——意思是:这份数据转成 JSON 文本再转回来,一个字节都不丢。

为什么 undefined 违约?因为 JSON 这个格式里根本没有 undefined 这个值。你在 Node 里跑 JSON.stringify({model: undefined}),得到的是 "{}"——字段整个消失了。所以「字段存在但值是 undefined」的数据没法无损地过 JSON 这座桥:过桥后字段就没了。宿主的校验(assertJsonArgs,在 ../packages/api/remotes/src/index.ts)专门拦这个:与其让数据在桥上悄悄缺胳膊少腿,不如当场拒收、大声报错。

名词卡二:广播(emit)与回滚(rollback)= 一次创建,全员监听,一票否决

你在 UI 里选工作区,前端发一个 session.create 请求。宿主创建会话成功后,不是闷头干完就完——它要广播一条事件(api-session/added),相当于向全楼喊「301 房入住了一位新客人!」,喊话内容里带着客人档案(会话摘要,summaryFor() 在 ../packages/api/session-controller/src/list.ts 组装——新架构把插件投影值也装进了这份档案,这就是条件 B)。

关键机制在 ../packages/core/session/src/index.ts 的 announce():任何一个听众抛错,整个创建作废(回滚)——会话从登记簿上撤下,已写的目录留下一个只有 header 的「孤儿」。这是宿主故意的设计(fail-loud 的一家):与其让一个说不清状态的会话进入系统,不如推倒重来。这次抛错的听众,就是把广播转发给浏览器并做 JSON 校验的那位(条件 C)。

最后一块:UI 前端收到失败后,静默清空了你的选择——catch 里连一句 console.warn 都没有。所以你看到的现象是「弹回」,而不是报错。这提醒我们验收 UI 时要多问一句:失败路径用户看得见吗?

名词卡三:版本钉住(pinning)= ^0.33.1 是一扇只开一条缝的门

package.json 里写 "dsh-context": "^0.33.1",这个 ^(caret)的意思是「允许兼容的升级」。但对 0.x 版本号,semver 规定 0.33 和 0.34 之间就算「不兼容」——所以 ^0.33.1 只允许 0.33.x 内的小修补,0.34 以后的任何版本,包括修复版,都进不来。插件作者 8/30 就发布了修好的 0.38.3,而你这扇门 9/4 之前从没开过。这不是 bug,是语义化版本的规则——但它的后果是:宿主大升级之后,被 ^0.x 钉住的插件要靠你手动推门。

你最初怀疑的三件事,不在场证明如下:改 package.json/cordis.patch.yml——与 8/30 备份逐字节比对,唯一差异是禁用 skills-deck,与链条任何一环无关;palette——不监听 api-session/added,其存储文件干净;mv-agent 等其他插件——无一人碰这条事件。真凶组合里没有「你昨晚做的事」,只有「你六天前做的一次 pull」和「你七天前装的一个插件」。

4. 回答你的两个疑问

「1.3k 星的好插件怎么会有恶性 bug?」——因为它当时没有 bug。它写的 model: undefined 对旧宿主完全无害,连它自己的数据校验(zod schema)都把这些字段声明成 optional,说明作者认为「没值」是合法状态。恶性不在任何单方,而在宿主收紧契约的速度快于生态跟进的速度时,中间必然存在一个「新旧配对必炸」的窗口期(8/28 宿主发版 → 8/30 插件修复,窗口约两天)。你恰好被 ^0.33.1 钉在了窗口里,而且六天没踩雷所以不知道。这不是插件质量差,是契约迁移——每个生态收紧规范时都会发生的事。

「触发原因只有它吗?」——直接原因(写入 undefined 的那只手)是它;但引爆开关是 8/29 的 pull,它一次带进了条件 B 和 C。三个条件里你手里握着两个可控的:pull 之前,一切平安;升级插件之后,一切恢复。说「都怪插件」和上次说「都怪 LM Studio」(LR-0002)是同一种归因错误——停在离现象最近的那个人身上。

5. 验收清单 +2(接第 5 课的清单)

  • 宿主大升级(几十个 commit 以上的 pull)之后,必做一次「新建会话」冒烟——只打开旧会话不算,那条路不经过创建链路。本次事故潜伏六天,就是缺了这一步。
  • 宿主跨版本升级后,主动检查被 ^0.x 钉住的第三方插件有没有新版本(npm view <pkg> time 十秒钟的事)——修复版不会自己走进来。
  • (给 dsh 维护者视角的你)两个可选加固:校验前移到投影写入时(点名插件,而不是炸整个创建);UI 的静默 catch 至少留一条 console.warn。失败必须可见,无论对插件作者还是对用户。

检索练习

① 为什么说 bug 出生在 8/29 23:29,而不是装插件的 8/27?

8/27–8/29 有五次成功创建的物证(投影缓存)。23:20 的 pull 带进「广播内嵌投影」与「JSON 校验」,23:29 第一次创建即留下孤儿尸体——三个条件首次同时为真。

② 「JSON 里没有 undefined」在校验时意味着什么?

JSON.stringify 会直接丢弃值为 undefined 的字段,往返之后数据缺了一块——所以「无损 JSON」校验当场拒收。转 null 是「有损的补救」,校验要拦的正是悄悄的丢失。

③ 插件作者 8/30 就发布了修复,为什么你 9/4 还在踩坑?

semver 对 0.x 的 caret 只在同一 0.33.x 内浮动;0.38.3 属于「不兼容升级」,必须手动改依赖。没有缓存或审核问题,是版本规则本身。

④ 宿主大升级后的冒烟测试,哪一种才算踩到了这次事故的路径?

出事的代码只在「创建」链路上:创建 → 广播 → 校验 → 回滚。打开旧会话、重启界面都不经过它——这正是事故能潜伏六天的原因。

动手验证(10 分钟)

  1. 亲眼看 pull 的时刻:在仓库跑 git reflog --date=iso | head -8,找到 2026-08-29 23:20:08 的 pull --ff-only。再跑 git log 47f943859b --oneline -1 确认 clone 起点,体会「16 天的架构差距一次到位」。
  2. 对比两具尸体:用 Node 解压 8/29 的 fa175ecb 和 9/4 的任一孤儿(会话目录里的 session.jsonl.zstd,Node 24 的 node:zlib 有 zstdDecompressSync)——两者都只剩一行 header。这就是「回滚」的物理形状。
  3. 看修复的样子:打开 ~/.dsh/profiles/web/node_modules/dsh-context/lib/index.js 搜 buildTimelineView,看 0.41.3 怎么用条件展开(...state.model !== void 0 ? { model: state.model } : {})做到「没值就不写字段」;再跑 npm view dsh-context time --json | tail -12 数一数修复窗口有几天。
