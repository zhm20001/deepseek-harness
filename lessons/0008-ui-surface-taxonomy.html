Lesson 0008 · Web UI 呈现方式

UI 的出场方式——你已无师自通四种,现在给它们正名

目标:15 分钟。把你 6 个插件里出现的 UI 形态对应到行业标准术语;拿到一张「什么时候用哪种」的选型地图;验收 AI 写的 webUI 时能说行话、能挑形态的毛病。
你的原话:「我意识到这似乎是 web 前端的几种展示页面的方式。它们的学名/术语都叫什么?还有其他种类吗?什么情况下适合用什么?」

1. 先正名:你的四个观察,学名对照

这批东西行业里统称 UI surface(呈现面),单个形态叫 UI pattern。逐条对上:

你的观察学名你机器上的标本技术指纹
usage-board 大盘「在原页面覆盖」 full-screen overlay(全屏覆盖层) GlobalBoard,挂宿主 shell.overlay slot position:fixed; inset:0; z-index:1000(globalBoardStyles.ts:37)
palette「原页面弹窗」 modal dialog,子类 command palette(命令面板) ⌘K 面板,自建 portal 到 document.body role="dialog" aria-modal + 焦点陷阱 + backdrop(PaletteBoard.tsx:1 注释自己就写着)
diary/simtrade/note-kanban「弹窗打开新页面」 standalone page in new tab(新标签页独立路由页) 侧栏锚点 <a href="/diary" target="_blank">(dsh-diary/src/client.js:42) 宿主 webServer.register 吐独立 URL 的整页 HTML
单 session 用量 / dsh-context 的「tab」 tab panel(标签页面板,ARIA Tabs Pattern) 都注册在 conversation.view slot(id: usage / context) role="tablist"/tab/tabpanel,方向键切换
一处措辞修正:diary 那组不是「弹窗」。它不是 dsh 页面里弹出的层,而是浏览器新开的标签页,里面装一个完全独立的页面。这一字之差正好是本课最关键的分界线,见下节。

2. 一条主轴看懂全部家族

别背十几个名词。所有 surface 的第一分叉只有一个问题:新内容和宿主页面是不是同一个 document?

  • 同 document(浮层系):overlay、modal、command palette、popover、drawer、toast——全都是「盖在原页面上」或「嵌进原页面」,和宿主共享 JS 上下文、状态、样式,通信就是函数调用。你的前两个观察在这边。
  • 新 browsing context:新标签页、window.open() 弹窗、iframe——浏览器另开一个独立页面,与原页面互不知晓,只能走 HTTP 或 postMessage。diary 那组在这边。

浮层系内部再分两刀:

  • 打断不打断:打断底层交互、圈住焦点的叫 modal(palette 的 Tab 键出不了面板);不打断的叫 modeless / popover / drawer。NN/g 的结论很干脆:modal 是打断税,只在"用户必须停下处理"时收(确认危险操作、一段完整输入),能免则免。
  • 生命周期:临时开关(modal,用完即走)、常驻切换(tab,一直都在,随时切)、并行同开(独立页面,两个窗口同时活着)。

「并行」是独立页面独有的能力——这也是 diary/看板选它的真实理由:你想一边在 dsh 里聊,一边在旁边写日记/拖看板。这件事 overlay 和 modal 在物理上就做不到:它们只要开着,就挡着宿主。

3. 易混的四组词

  1. overlay vs modal:overlay 是实现词(一层盖上去的视觉结构),modal 是行为词(打断 + 圈焦点)。你的两个标本恰好各占一边:GlobalBoard 是 overlay 但不算典型 modal(没有把背景变 inert);palette 是 modal(有焦点陷阱)。判据永远看行为,不看 z-index 高低。
  2. dialog vs modal:dialog 是容器概念,modal 形容"阻断模式",所以存在 modeless dialog(开着但不妨碍你操作背景,经典如编辑器的查找替换)。原生 <dialog> 元素自带双证件:show() = modeless,showModal() = modal。
  3. popup 的语义漂移:历史上 popup 专指 window.open() 的浏览器弹窗(被广告做坏名声的那位);如今口语常指页面内小浮层,正式名叫 popover。写文档说清楚用哪个,别用 popup 这个含糊词。
  4. 两种 tab:页面内 tab(tablist/tabpanel,ARIA Tabs Pattern)≠ browser tab(浏览器标签页)。你的第 4 个观察是前者,第 3 个观察打开的是后者——中文都叫「标签页」,层级完全不同,这是你自己观察里暗埋的混淆点。

4. 家族全景(还有谁?)

你没用到但同家族的,按主轴归位——完整速查表见参考文档 · UI Surfaces 术语表:

  • 浮层系:drawer / side panel(边缘滑入的面板;dsh 细节栏本质就是它)、popover(锚定触发元素旁,点外即关)、tooltip(hover 提示)、toast(自动消失的通知条)、bottom sheet(移动端从底部滑入)、lightbox(媒体放大查看)。
  • 非浮层系:inline disclosure / accordion(不浮起,原地展开,<details>)、route view(SPA 路由切换主内容区,URL 可分享——dsh shell 自身页面切换就是它)。
  • 新 context:popup window(window.open,OAuth 回调常用)、iframe embed(页面里嵌第三方页面,样式脚本隔离)。

5. 选型:四问,按顺序

  1. 要并行使用吗? 用户要同时看主界面和这个内容(边聊边写/边看) → 只有新标签页独立页能做到。diary/simtrade/看板全在这一格,判断正确。
  2. 内容归属于谁? 归属某个已有容器("这个 session 的另一种视角") → tab panel;锚定某个按钮/字段 → popover;辅助信息半屏对照 → drawer。usage-board 的单 session 计费挂 conversation.view,归属判断也对。
  3. 必须打断吗? 用户不处理完不能继续(危险确认、整段必填输入) → modal;否则不要 modal。palette 例外地合理:命令面板的语义就是「唤起即专注」,搜完即走。
  4. 体量与驻留 小而瞬态(toast/tooltip)→ 中而临时(popover/modal/drawer)→ 大而常驻(tab/独立页)。usage-board 大盘是全屏 overlay 而非独立页,换来的是它能直接读宿主状态、样式同源——体量到了边界,但生命周期「临时开关」是对的。

6. dsh 工程视角:主轴即通信方式

那条主轴在 dsh 里有个非常工程化的读法:同 document = 函数调用;新 browsing context = HTTP API。

  • tab / overlay / modal 都活在 dsh 的 React 树里,拿 sessionId 靠 props 注入(SessionPanel 就是),要什么状态直接调用——但受宿主运行时约束,要带构建。
  • diary 的独立页和 dsh 只通过 webServer.register 的 /diary/api/* 说话。代价是两边只有 HTTP;收益是完全自由——它是零构建的 vanilla HTML,根本不进 React 树(第 7 课的样式问题在这边也简单一半)。
  • palette 是第三条路:slot 体系当年管不到覆盖层,它就自己 portal 到 document.body(portal.tsx:61 注释明说)。属于「非官方逃生门」——能用,但要比官方 slot 多自己操心焦点陷阱、层级和卸载。

7. 检验你的理解

① 你要给「正在进行的 session」加一个用量统计,用户想一边聊一边随时切过去看。选哪种 surface?

归属 session、常驻、不打断聊天——三问都指向 tab(现实里 usage-board 正是这么挂 conversation.view 的)。overlay 会盖住聊天;独立页割裂了「这个 session 的视角」归属。

② palette 的 ⌘K 面板被归为 modal 而不只是 overlay,判据是哪一个?

modal 是行为词不是视觉词:背景 inert + Tab 出不去(焦点陷阱)。z-index 和全屏都只是 overlay 的实现细节——GlobalBoard 也全屏,但不算典型 modal。

③ diary 打开的 /diary 页面,与 dsh 主页面之间的关系是?

新标签页 = 新 browsing context,两个 document 互不知晓,只经 /diary/api/* 的 HTTP 通信。这就是「边聊边写」可行的原因,也是它敢用零构建 vanilla HTML 的原因。

8. 深入阅读

主推:WAI-ARIA Authoring Practices Guide 的 Pattern 目录——W3C 官方的 UI 模式大全,每个 pattern(dialog、tabs、disclosure…)带 ARIA 语义、键盘交互和可运行示例,是「学名」的最终出处;验收 AI 写的组件时拿它当清单。配合 NN/g 的 Modal & Nonmodal Dialogs(什么时候该/不该打断,选型判断的实证依据)与 MDN 的 <dialog> 页(原生双证件 show/showModal)。

有不清楚的地方,随时问你的老师(也就是我)。下一步可以做一节动手课:给 palette 之外再挑一个形态(比如 drawer 或 toast),让 AI 实现一版,你来按本课的四问验收它选的形态对不对。
