dsh 追更速查表

Lesson 0006的压缩版。忘了才翻,不背。

四层管线:版本不对,先定位层

层看哪更新命令验收方法
① 源码clone 工作区git pull --ff-onlygit log --oneline -1
② 依赖node_modules(不进 git)pnpm installinstall 输出无 error
③ 构建产物apps/cli/lib/ 等(不进 git)pnpm run buildlib/ 时间戳是新的
④ 命令PATH 目录里的可执行文件本方案无需动(wrapper 指向③)dsh --version

追更口诀(当前方案:clone + wrapper)

cd ~/deepseek-harness
git pull --ff-only && pnpm install && pnpm run clean && pnpm run build
dsh --version          # 验收:应等于 GitHub master 的版本

全局命令的真实身份:~/Library/pnpm/bin/dsh 是一个 3 行脚本,exec node ~/deepseek-harness/apps/cli/lib/bin.js "$@"——指向 clone 的③层产物,build 后自动变新。不要再 pnpm add -g @deepseek-ai/dsh,会覆盖 wrapper 回到冻结拷贝。

git 速查

命令一句话
clone首次下载整份历史 + 铺工作区(只有①层)
pull= fetch(下载新提交)+ merge(分支前移);是合并不是同步,脏文件重叠时会拒绝执行
status / log -1看 ahead/behind 与当前提交——pull 后必看
diff工作区 vs 最近提交的差异;pull 前先看自己改了什么
stash / stash pop脏修改压栈 / 取回;让 pull 畅通
restore <file>丢弃工作区修改(想清楚再敲)

pnpm 速查

命令一句话
install按 lockfile 同步 node_modules(②层)
run clean清旧构建产物和已删包残留(build 前)
run build编译出 lib/(③层);魔改源码后跑它即生效
view <pkg> version看 npm 已发布版本(常落后于 master)

症状 → 诊断 → 解法

症状先查解法
dsh --version 比 GitHub 旧①层:git log --oneline -1、git status落后 → 追更口诀;不落后 → 看④层 cat $(which dsh) 指向哪
pull 报 local changes would be overwrittengit diff 看改动要不要不要:git restore <file>;要:git stash → pull → git stash pop(冲突则手动改)
command not found: dshwhich -a dsh、echo $PATHPATH 目录里没有入口文件:重建 wrapper(见上)或 pnpm add -g
build 后行为仍是旧的ls -l apps/cli/lib/ 时间戳pnpm run clean && pnpm run build 清残留重建
全局 dsh 版本"永远不动"pnpm ls -g装的是冻结拷贝(打包/npm)——换 wrapper 或每次重装

底线三句

  • 命令只是 PATH 上的一个可执行文件;"注册"= 把文件放进 PATH 目录。
  • 每层只认自己的更新命令;git 管不到④,pnpm 管不到①。
  • pull 是合并,会拒绝、会被看漏——执行后必须 git log -1 验收。
