# 命令只是 PATH 上的文件;pull 过了不等于更新了

两个 misconception 在 2026-08-29 的事故中被证据纠正:①用户以为"执行过 pull = 仓库已更新"——实际 pull 因本地脏文件被拒绝执行,仓库落后 origin/master 1933 个提交而未察觉;②用户以为"仓库更新了 = 全局 dsh 命令也会更新"——实际 8-22 手动 pnpm add -g 装的是冻结拷贝,与仓库零关联。修复后全局 dsh 改为指向 clone 构建产物的 wrapper(④层指向③层,不再快照)。

**Evidence**:用户看到 `git status` 的 behind 1933 输出后自行承认"确实我没有 pull 成功,我看漏了";随后主动用新模型推理("clone 源码不需要 dsh 就可以直接从 js 文件执行……顺手注册了 dsh 比较好?"),说明已开始用四层管线(源码→依赖→构建→命令)组织工具链认知。

**Implications**:git/pnpm/命令注册的工具链层不用再从零教;但本次是"讲解+执行",四层模型未经独立复述检验——下次课开头做一次检索练习(画出四层 + 解释 bin 字段),过了才确认内化。用户已确立"clone + wrapper + 追更口诀"的长期工作流,后续教学环境变更(如 apps/cli 挪位置)需提醒 wrapper 路径依赖。
