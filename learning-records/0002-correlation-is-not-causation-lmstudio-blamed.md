# 相关不等于因果:本地模型被冤枉了(exit 1 事故)

用户曾把 dsh 连续 exit(1) 归因于「换了 LM Studio 本地模型」;调查证明根因是 dsh-usage-board 插件的签名错配(把 sessionId 字符串传给收 Session 对象的宿主 flush)叠加定时器 fire-and-forget,与模型无关——三个时间巧合(插件重写后首次真实对话、27B 模型首 token 要 131 秒、崩溃恰好落在工具调用后 250ms 的落库定时器)制造了因果错觉。用户看到证据后自行修正为「这看起来是这个插件的原生 bug,只是我从未触发过」(2026-08-28;事故全记录见 `~/projects/usage-dashboard/dsh-usage-board/docs/incident-2026-08-27-exit-1.md`,修复 commit 7750c36,讲解 Lesson 0005)。

## Evidence

- 用户原话:「这看起来是这个插件的原生 bug,只是我从未触发过」——主动放弃错误归因并说出「从未触发」(潜伏期概念),是 misconception 修正的标志。
- 用户能主动补充关键线索(新装 2 个插件 + 换模型),说明已具备「变量隔离」的直觉,只是初始排序把模型排在了第一位。

## Implications

- 后续教异步/Promise/调试课时,「相邻 ≠ 因果」「时间巧合叠出错觉」是他亲历过的锚点,直接引用本次事故即可,不必从零举例。
- 对「手写镜像类型 + mock 一起骗过测试」这一坑已有一手体感;教契约测试(对真身对账)时以此为案例,预期接受度高。
- 尚无证据表明他能独立读崩溃栈——Lesson 0005 刚教「从下往上读」。下次课先验收这一技能再决定是否深化。
